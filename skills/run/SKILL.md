ユーザーが ensemble での委譲を明示的に求めた。この依頼1回分だけ、次のとおりに進める。モードとして以降の会話に持ち越さない。

対象: $ARGUMENTS

対象が空なら、この会話で未完了の作業を対象にする。最初に、完了済みの内容・残りの作業・未決の判断を3〜5行で整理する。以降の調査や長い出力を伴う作業は specialist に寄せ、本体の文脈は判断と統合に使う。

## 進め方

1. 対象を互いに独立したタスクに分ける
2. タスクごとに担当を決める。直接やるほうが速く確実なものは本体が直接やる。工程を埋めるための委譲はしない
   - ensemble:explore: 場所や仕組みを知らない。往復の多い調査を結論だけにしたい
   - ensemble:architect: API、データ構造、モジュール境界など、後戻りしにくい設計判断がある
   - ensemble:implementer: 互いに独立した実装、機械的な大量変更
   - ensemble:test-runner: 全体の test / build / typecheck、長いログを伴う検証
   - ensemble:reviewer: 非自明なロジックや公開 API の変更を、コミット前に確認する
3. 分担を「タスク・担当・理由」の1行ずつで短く示し、そのまま着手する
4. 依存しないタスクは1メッセージ内で並列に起動する。依存するタスクは、前の結果を見てから次を決める
5. specialist の結果は自分で確かめてから統合する。「通ったはず」を根拠にしない

## 守ること

- specialist を呼ぶ順番は固定しない。前の結果を見て、次の specialist が不要なら呼ばない
- specialist に渡す指示には、そのタスクに必要な文脈だけを具体的に書く（目的、対象ファイル、完了済みの内容、返してほしい形）
- 設計の選択やユーザーの確認が必要な点が出たら、確定せずにそこで止めて確認する
